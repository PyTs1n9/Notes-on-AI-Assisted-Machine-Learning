## 四、待修正清单（按顺序改）

### bug① `data_profile.csv` 多出 16 行重复记录（49 行，应为 33 行）

- 现象：`dateset` 计数 day=32、hour=17；day 的 16 个字段被登记了两遍。
- 原因：`make_rows` 往**全局** `rows` 里 append，最后 `return rows` 把全局列表整个还回来。`table += make_rows(df_day, ...)` 先收进 16 行；第二次 `table += make_rows(df_hour, ...)` 收到的却是「day 16 ＋ hour 17 ＝ 33 行」，day 就被算了两遍。
- 改法：函数内部建**局部**列表再返回，别碰全局变量：

```python
def make_rows(df, name):
    out = []                      # 局部列表，每次调用都是全新的
    for col in df.columns:
        s = df[col]
        # ...原有的 if/else 计算不动...
        out.append({'dateset': name, 'column': col, # ...字段照旧...
        })
    return out                    # 只返回本次这一份
```

### bug② 两个范围统计 CSV 丢了行标签

- 现象：`df_day_stats.csv` 打开后只有 count, mean, std, ... 四行数字，对不上哪行是 cnt／temp／hum／windspeed：


- 原因：`describe().T` 之后，行索引就是这四个字段名；`to_csv(index=False)` 把索引整列扔掉了。
- 改法：两处 `df_stats.to_csv(..., index=False)` → `df_stats.to_csv(..., index=True)`，重跑后 CSV 第一列会出现字段名。

### bug③ 等式验证拿不出证据

- 现状：`print(df_day['casual'] + df_day['registered'] == df_day['cnt'])` 打印整列布尔，控制台显示成 `0 True / 1 True / ... ... / 730 True`，中间被省略号吃掉，不能证明「全部为 True」。
- 改法：两个数据集各改成打印 `.all()`，各输出一个 `True`：

```python
print((df_day['casual'] + df_day['registered'] == df_day['cnt']).all())    # 输出 True
print((df_hour['casual'] + df_hour['registered'] == df_hour['cnt']).all())  # 输出 True
```

### bug④（顺手改，不挡过关）日期键重复检查选错了键

- `day.csv` 没有 `hr` 列。你环境的 pandas 2.3.3 遇到 `subset` 里不存在的列会**静默忽略**，所以侥幸跑通，等价于只查了 `dteday`（结果 0，数值没错）；但同一份代码在 pandas 3.x 下会直接报 `KeyError: Index(['hr'])`（我在课程环境实测确认）。按数据集选键：

```python
key_cols = ['dteday'] if name == 'day' else ['dteday', 'hr']
```
