# 江苏省职业院校技能大赛“人工智能应用”综合实战考核

## 项目：智慧城市运营分析与公共场景智能识别
**考试时间：600分钟（10小时）｜满分：100分**

### 一、项目背景
某城市公共服务管理部门拟建设一个AI辅助分析原型，需完成四项工作：共享单车需求预测、租赁日期分群、公共场景图像识别，以及技术报告编制。两套数据分别用于运营预测分析与视觉识别，不进行跨数据集记录关联。

### 二、数据与环境
- `data/bike_sharing/hour.csv`、`day.csv`：UCI 2011—2012年真实共享单车历史数据。
- `data/coco128/images/train2017/`、`labels/train2017/`：COCO128真实图像与人工标注。
- Python、pandas、numpy、scikit-learn、matplotlib、seaborn、opencv-python、torch/torchvision、ultralytics、PyYAML。
- 统一设定随机种子`42`，保存软件版本与设备信息。原始文件须保持不变，全部处理结果存入`submission/`。

### 三、考核时间安排
| 阶段 | 时长 | 目标 |

## 任务A1：真实租赁数据审计（10分）
1. 读取两份CSV，输出各自`shape`、字段名称、字段类型、`head()`、`describe()`结果。
2. 统计每列缺失值数量、完全重复行数量、`instant`或日期键重复情况，形成审计表。没有发现缺失或重复时，应将实际统计值记为0。
3. 对`cnt`、`temp`、`hum`、`windspeed`统计范围；至少对`cnt`使用IQR方法**识别并保存**异常候选行，并依据业务含义判断是否进行处理。
4. 验证`cnt == casual + registered`，说明将`casual`、`registered`加入`cnt`预测特征会产生什么问题；如实解释本数据中是否存在可直接识别个人的字段。
5. 形成`data_audit.md`、`data_profile.csv`、`outlier_candidates.csv`及用于后续任务的`hour_clean.csv`、`day_clean.csv`。

## 任务A2：共享单车小时需求回归预测（22分）
**预测目标**：使用历史环境与日期特征预测小时租赁总数`cnt`。
1. 建立特征表X和标签y；X不能包含`cnt`、`casual`、`registered`、`instant`；处理`dteday`，确保模型输入无原始字符串列或缺失值。
2. 按`train_test_split(test_size=0.2, random_state=42)`划分训练与测试。所有`StandardScaler`只在训练集拟合，禁止使用测试集的信息计算变换参数。
3. 训练`LinearRegression`、`Ridge`、`Lasso`三个模型；分别计算MAE、MSE、RMSE、R²，输出`regression_metrics.csv`和测试样本的`regression_predictions.csv`。
4. 对Ridge、Lasso比较至少4个不同`alpha`值，用训练集完成5折交叉验证；报告最优参数及平均CV分数，测试集不参与参数选择。
5. 绘制`regression_scatter.png`（真实值与预测值）及`regression_model_compare.png`（至少1个指标的模型对比），报告两个误差较大的样本并分析可能原因。
6. 用不超过200字说明：哪个模型更好？预测值与实际值产生偏差的原因是什么？根据模型评价指标和实验结果论证结论。

## 任务A3：KMeans运营日期分群（13分）
1. 以`day_clean.csv`为输入，至少使用`temp`、`hum`、`windspeed`、`cnt`四项数值建立日期聚类特征（可添加其他合理特征）。
2. 使用`StandardScaler`，计算`K=2~8`每个K的Inertia、Silhouette Score、Davies–Bouldin Index，保存为`kmeans_scores.csv`。
3. 绘制`elbow_curve.png`及一张二维聚类散点图（可选`temp`和`cnt`作为坐标轴，但须说明它只是二维投影），选择一个最终K并解释理由。
4. 输出含日期、聚类编号的`daily_clusters.csv`以及每个簇各特征均值、数量的`cluster_summary.csv`。
5. 根据结果用自然语言给每个簇命名，如“高需求温暖日”“低需求寒冷日”，名称必须有统计依据，而非事先硬编码。

## 任务B1：真实照片核验、标注抽检与增强（10分）
1. 统计128张真实图像的尺寸、通道数、文件格式，形成`image_profile.csv`。
2. 检查YOLO文本每行是否为`class x_center y_center width height`；类别应在`0~79`，中心坐标及宽高应处于合理归一化范围，框不应越界（`x±width/2`、`y±height/2`边界也需检查）。
3. 记录空标签、缺失标签、非法框数。逐项记录实际核验结果；抽取至少8张图进行带框可视化，保存到`label_preview/`。
4. 选取训练集中的至少10张图进行亮度调整和水平翻转两类增强，保留真实原图，输出对应增强图。翻转时必须对YOLO标签同步变换（如水平翻转后新中心横坐标为`1−x_center`）；不能仅翻转图片而沿用旧坐标。
5. 输出`label_audit.md`、`augmentation_examples/`与增强方法说明。

## 任务B2：ResNet18判断场景是否有人（16分）
1. 利用COCO128现有YOLO标注构造二分类标签：存在类别0（person）为`has_person`，否则为`no_person`。输出每类图片数量。
2. 按原始图片文件名将图片分为**互不重叠**的训练/验证集，比例建议80/20，随机种子42。可采用`ImageFolder`要求的目录结构，不得把同一张图片的增强版本放到两侧。
3. 使用ImageNet预训练`ResNet18`，修改最后全连接层为2类；至少训练3个epoch，完成`train()`、`eval()`、损失统计和最佳模型保存。若本地CPU性能有限，可冻结backbone，仅训练最后分类头，但必须说明。
4. 输出验证集Accuracy、Precision、Recall、F1及Confusion Matrix，保存`resnet_metrics.csv`、`resnet_confusion.png`、`resnet_best.pth`、`resnet_training_curve.png`。
5. 写100～200字分析：哪类图容易识别错误？样本量只有128张对模型评价有何影响？

## 任务B3：YOLOv8目标检测（19分）
1. 基于COCO128，将**原始照片按文件名**分成约80%训练、20%验证，复制图片及配套TXT到`yolo_data/images/train|val`、`yolo_data/labels/train|val`，不得沿用官方示例的训练集=验证集设置。
2. 写`data.yaml`（保持COCO80类别名、索引一致）并编写数据集完整性检查，验证无图片跨集合、标签/图片对应，增强图片不能出现在验证集。
3. 加载**`yolov8n.pt`**预训练权重并微调。参考参数`epochs=5, imgsz=416, batch=8, seed=42`，按显卡情况可适度减小；记录设备、训练轮次、耗时。若只有CPU，请在报告中注明，至少完成1个完整epoch并进行验证。
4. 保存最佳权重`yolo_best.pt`，记录验证集Precision、Recall、mAP@0.5、mAP@0.5:0.95，生成`yolo_metrics.csv`。
5. 对验证集至少10张图进行推理并保存带框图片至`yolo_predictions/`；分析至少2个漏检或误检案例。如未发现可确认的错例，应说明核验范围并讨论潜在风险。
6. 解释为何COCO128的小样本实验能否直接代表实际部署场景的准确程度；评估以数据划分、训练可复现、指标正确及分析合理为准。
